# 2026-10-21 網站問題修復範圍與驗收

## 任務與邊界

## 已確認問題與預期行為

- UUID 大小寫：完整 UUID／8 碼 ID 都導向同一個小寫 canonical；帶大寫 UUID 的合法維護請求也必須讓已暖的小寫 HTML、metadata、RSC 更新。slug 維持原有大小寫語意。
- 搜尋：重複 `q` 取第一值；保留畫面上的 `%`、`_`、反斜線，只在建立查詢時跳脫一次。資料服務失敗必須進錯誤畫面，不能冒充零結果。
- 標籤／比較網址：Next.js 已解碼的參數不可再次解碼，合法百分比文字不能讓頁面崩潰。
- Next.js 16.0.7 的 ISR matcher 會再次解碼 cache key；僅 literal 含 `%` 的標籤／比較網址，proxy 改寫到不同 prefix 的 `/internal/tags/<hex>` 或 `/internal/compare/<hex>`。薄轉接頁保留 3600 秒 ISR，重用原頁與 metadata，對外 canonical 仍為原網址。hex 僅接受可無損往返的 UTF-8，非法 key 為 404、非法公開編碼為 400。內部路由是公開唯讀內容，不是私密 API，沒有 DB 寫入或外站轉址。
- 收藏：登出、換帳號時立即遮蔽上一位使用者的資料；過期讀取、同步完成、寫入失敗不能覆寫新帳號。保留匿名收藏與登入後同步；損壞本機資料不能卡住載入狀態。
- 載入失敗：新聞列表失敗後停止自動重試並提供手動重試；缺少英文時先顯示可讀原文。熱門新聞、搜尋與批次翻譯不因重新渲染或切換語言而形成重試循環。
- 公開資料：首頁、歷史、週報、月報、精選、比較、趨勢與 sitemap 區分真正空資料和上游故障。故障要拋錯以保留已有 ISR，不產生虛構新聞；RSS 故障回 `503`、`no-store`，健康的空 RSS 仍回 `200`。
- 對讀者顯示簡明錯誤、手動重試與回首頁，不能洩漏上游錯誤內容。

## 驗證方式

- 使用 Node.js 24 和鎖定依賴；現有 lint、全部單元回歸、真正 `next build --webpack`／`next start` 的隔離 HTTP fixture。
- 對每項已修問題先保留失敗證據，再確認修正後通過；收藏與重試測試驅動實際 hook／元件的非同步與重新渲染行為。
- 正式模式測試包含新聞／標籤 MISS→HIT、HTML／RSC、舊連結 GET／HEAD／RSC 單一 308、成功寫入後失效、負快取恢復與 DB 故障後恢復；不使用正式金鑰、正式 DB 或付費 AI。
- 本機測試只證明程式行為，不等於正式站恢復或 Vercel 歷史命中率。正式部署與平台驗收仍需另行授權。
